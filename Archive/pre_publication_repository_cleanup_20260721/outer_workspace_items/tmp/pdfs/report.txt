                                      Abstract                                    
            This report audits the Stage 4F.1b semantic-completion, lease-recovery, and real-runner-hardening package
           for the GraphKAN AMO neural-quantum-state project. The release is correctly framed by the student as
           engineering-onlyandretainsthefrozen960-runopen/periodicStage4Fprotocolwithoutlaunchingit. Theouter
           SHA-256 and ZIP integrity pass; the exact-name internal manifest validates 147 files; the registry contains 960
           unique work items; the four release tests pass when the scripts directory is added to PYTHONPATH; the supplied
           corruption suite rejects eight direct mutations; and an 80-process local claim probe produces 80 distinct claims.
           These are real improvements over the previous Stage 4F.1 prototype. They are not sufficient for acceptance.
           Independent testing found that nine of nine scientifically invalid but self-consistent bundles are accepted; the
           golden checkpoint is plain text rather than a readable NPZ/Flax state; campaign validation does not reconcile
           registryandfilesystemstate; theprotocolhashomitssourceandschedulersemanticsandcannotbereproduced
           from the release; heartbeat and attempt fencing are absent; configured retry limits are ignored; concurrent
           promotion is not no-replace safe; and the real worker remains a placeholder that exits zero after failure. The
           report therefore classifies Stage 4F.1b as a material partial repair, rejects both the current microcampaign and
           Stage 4F-R launch, and defines one bounded Stage 4F.1c closure gate. The long-term scientific route remains a
           boundary-aware Rydberg NQS benchmark and mechanism/failure-map study, not a KAN-superiority paper.

       1  Executive Verdict and Strategic Position                                
                                                                                  
                                                                                  
       1.1 Three separate verdicts                                                
                                                                                  
         A. Current-evidence verdict – ORANGE                                     
         Approve Stage 4F.1b as a material internal repair, but do not mark its acceptance gate complete.
         ThepackageclosesseveralshallowfailuremodesfromStage4F.1anddemonstratesusefullocaldatabase/claim
         mechanics. It does not yet define a scientifically trustworthy completed run.
                                                                                  
         B. Next-iteration verdict                                                
                                                                                  
         Approve only Stage 4F.1c: Schema-Fenced Real-Runner and Crash-Recovery Gate. The required
         order is: (i) self-contained release and content-addressed protocol identity; (ii) typed artifact schemas and
         actual checkpoint loading; (iii) bidirectional registry/filesystem reconciliation; (iv) heartbeat plus attempt
         fencing; (v) no-replace promotion and bounded retry/quarantine; (vi) real runner integration; (vii) four-real-
         run smoke; (viii) a redesigned 16-run microcampaign with deliberate process kills; and (ix) independent
         replay.                                                                  
                                                                                  
         C. Long-term scientific and publication verdict                          
                                                                                  
         The project remains scientifically alive, but none of the present engineering work is a physics result or
         publication novelty. A credible specialist-journal paper would require a complete, preregistered boundary-
         patch campaign showing where boundary-aware pair features help, trade off, or fail relative to strong
         MLP/RBM and physics controls. Physical Review A remains the most natural physics venue; Machine
         Learning: Science and Technology becomes plausible if the benchmark and reproducibility artifact are the
         main contribution. Quantum remains a stretch because its stated threshold requires a very significant
         contribution beyond the state of the art, not merely correct infrastructure or incremental model comparisons
         [1, 2, 3].

       3  Scientific Question and Contribution Logic                              
                                                                                  
                                                                                  
       3.1 The actual scientific question                                         
                                                                                  
       The frozen Stage 4F scientific question is whether boundary-aware RBF pair variants produce a reproducible open-

       5.4 Semantic validation architecture                                       
                                                                                  
       The current validator is primarily a presence-and-hash checker. It confirms that selected files exist, that declared
       hashes match current bytes, that CSVs contain a run_id column, and that selected IDs agree. It does not establish
       that the files have the required scientific content.                       
       A fail-closed scientific validator must implement all of the following:    
                                                                                  
       1. exact schemas, dtypes, allowed enums, row counts, and index domains;    
       2. finite numerical values for all required metrics;                       
       3. consistency between configuration, registry, metrics, observables, history, checkpoint metadata, and directory
         identity;                                                                
                                                                                  
       4. actual checkpoint restoration through the same Flax/NetKet path used by analysis;
       5. complete artifact-manifest coverage and safe bundle-relative paths;     
       6. content hashes bound into COMPLETE.json;                                
                                                                                  
       7. registry status/path/hash reconciliation;                               
       8. attempt token and current-owner verification;                           
       9. rejection of any unknown, missing, duplicated, or stale canonical artifact.

       5.8 Lease recovery, fencing, and retries                                   
                                                                                  
       The stale-row command can demote an expired row, but the worker never emits heartbeats. More seriously,
       ownership is identified only by worker ID, not by a unique attempt token. In the independent probe, worker A’s
       late completion was correctly rejected after worker B reclaimed the row, but worker B could accept worker A’s
       bundle. This is a classic stale-writer problem. The bundle must carry a claim UUID generated atomically at
       assignment; only the current claim UUID may transition the row to COMPLETE.
       The configured max_attempts value is also not inserted into registry rows, so the database default wins. There
       is no demonstrated timeout, exponential backoff, final-failure transition, or quarantine lifecycle. These are not
       optional for a long campaign with deliberate process interruption.         
                                                                                  
       5.9 Promotion and collision semantics                                      
                                                                                  
       Thecodecheckswhetherthefinaldirectoryexistsandthencallsos.replace. Inaconcurrentempty-directoryprobe,
       both promoters reported success. Sequential retries are blocked by an existing invalid final directory. Production
       behaviour must be one of: no-replace atomic rename; byte-identical collision reconciliation; or conflicting-attempt
       quarantine. Silent replacement or permanent blockage is unacceptable.      
                                                                                  
       5.10 Campaign-wide reconciliation                                          
                                                                                  
       A campaign validator must establish a bijection between terminal registry rows and canonical bundles. The
       submitted command only scans directories containing COMPLETE.json. It therefore misses:
                                                                                  
       • registry COMPLETE rows with missing directories;                         
       • bundles whose registry row is PENDING or FAILED;                         
       • registry completion-hash mismatches;                                     
                                                                                  
       • orphan directories;                                                      
       • duplicate attempt directories;                                           
       • renamed or swapped run directories;                                      
                                                                                  
                                                                                  
                                       14 of 32                                   
                                                                                  

                                                                                  
       GraphKAN AMO NQS Stage 4F.1b audit               Prepared for supervisory review
                                                                                  
                                                                                  
       • terminal failures without preserved evidence.                            
                                                                                  
       Independent tests confirmed successful exit under both a missing COMPLETE bundle and a changed completion
       hash.                                                                      
                                                                                  
       5.11 Real-run path and truthful process status                             
                                                                                  
       The –real-run branch is intentionally a placeholder. The worker catches the resulting exception, records
       FAILED_RETRYABLE, prints an error, and exits zero. A batch shell, supervisor, or CI system will interpret
       this as success. The orchestrator must return nonzero when requested work has not reached the required terminal
       state, even if individual failures are correctly recorded in the database. 
                                                                                  
       5.12 SQLite deployment boundary                                            
                                                                                  
       The local claim test is useful evidence for a same-host local filesystem. It does not support a shared network-
       filesystem registry. SQLite’s official WAL documentation requires all processes to be on the same host and states
       that WAL does not work over network filesystems [4]. For multiple team machines, use one of:
       1. independent per-host registries and immutable bundles, followed by offline merge;
                                                                                  
       2. a single-host coordinator/proxy that owns the SQLite database;          
       3. a client/server database if central multi-host claiming is truly required.

       6  Experimental  Design and Validity Audit                                 
                                                                                  
                                                                                  
       6.1 Registered physics protocol                                            
                                                                                  
       ThefrozenStage4Frosterremainsscientificallysensible: twoboundaryconditions,fourdetunings,threeinteraction
       strengths, five seeds, and eight model/control families, for 960 runs. The unit of analysis is a paired seed within a
       Hamiltonian cell. Energy, density, and connected-correlation errors are co-primary; runtime is a secondary resource
       metric. The protocol should remain unchanged until engineering acceptance. 
                                                                                  
       6.2 Current Stage 4F.1b design                                             
                                                                                  
       Stage 4F.1b is not a statistical physics experiment. Its units are registry rows, validator cases, lease attempts,
       and worker processes. The relevant quality measures are false accept, false reject, duplicate canonical completion,
       unreconciled state, failed recovery, and truthful terminal status. P-values are inappropriate here; exact pass/fail
       counts and adversarial coverage are more informative.

       7.2 Practical interpretation                                               
                                                                                  
       The direct-corruption rejection rate demonstrates progress from Stage 4F.1. The independent false-accept rate
       demonstrates that the validator remains structurally permissive. The 80-process result supports a local claim
       transaction; it does not establish multi-host safety, completion semantics, or crash recovery. The two mock
       completions support only the happy path encoded by the same implementation under test.
                                                                                  
       7.3 Statistical interpretation                                             
                                                                                  
       No inferential significance test is warranted. The validator requirement is zero false accepts on a prospectively
       defined adversarial suite. Observing 9/9 false accepts is a decisive engineering failure independent of a confidence
       interval. Similarly, the claim-lock probe is a bounded local stress test, not an estimate of global exactly-once
       reliability.                                                               
                                                                                  
       7.4 No new scientific performance statement                                
                                                                                  
       The current package must not be combined with earlier partial Stage 4F outputs to make a scientific claim. The
       scheduler repair changes what counts as a trustworthy row. Until the full protocol is rerun or reconciled under the
       accepted state machine, earlier execution-order selected rows remain exploratory legacy evidence.
                                                                                  
       8  Failure Autopsy: Why  Stage 4F.1b  Still Fails                          
                                                                                  
                                                                                  
       8.1 True repair versus false assurance                                     
                                                                                  
       This iteration is not a failed effort. It genuinely repairs known direct corruptions and stale-row handling. The
       problem is that the tests validate implementation-specific symptoms rather than the invariant: “a canonical
       COMPLETE bundle is the exact, immutable, scientifically valid output of the current claimed attempt under the
       frozen protocol.”                                                          
       The student has moved from a presence-only validator toward a hash-and-ID validator. The remaining gap is
       semantic closure and state-machine authority.                              
                                                                                  
       8.2 Root causes                                                            
                                                                                  
       1. No formal artifact contract. CSV and YAML files have no versioned typed schemas; therefore “valid”
         means “contains a few expected names.”                                   
       2. Metadata is trusted instead of recomputed. The checkpoint sidecar says readable; the validator does not
         restore the checkpoint.                                                  
       3. Identity is partial. Protocol,run,config,code,environment,schema,attempt,andcanonical-bundleidentities
         are not one closed chain.                                                
                                                                                  
       4. Registry and filesystem are treated separately. Directoryvalidationanddatabasestatearenotreconciled.
       5. Attempt ownership is not fenced. Worker names are not unique attempt capabilities.
       6. The test oracle is too close to the implementation. Direct mutations are caught, but adversarially
         regenerated self-consistent invalids are not.                            
                                                                                  
       7. Real integration is deferred. Mock artifacts cannot reveal actual Flax PyTree, NetKet logging, checkpoint,
         timeout, or subprocess behaviour.                                        
                                                                                  
       8.3 Negative result value                                                  
                                                                                  
       This is an informative engineering negative result. It localises the next uncertainty: the database roster is no
       longer the principal blocker; semantic artifact contracts and attempt-state closure are. It also sets a rational stop
       condition. If one more bounded patch cannot close these invariants, the bespoke orchestration layer is consuming
       more research value than it creates.

       10  Repair Hypotheses  and Redesign  Options                               
                                                                                  
                                                                                  
       10.1 Preferred repair: close the invariant chain                           
       The preferred design is a content-addressed run bundle with a single authoritative attempt token:
                                                                                  
                        protocol hash→run identity→claim token                    
                                                                                  
                                 →resolved config→artifacts                       
                                 →artifact manifest→COMPLETE hash                 
                                 →registry commit.                                
       Every arrow must be recomputable and checked. The registry transition to COMPLETE must be conditional on
       the current claim token and the expected pre-completion status. A later worker may not adopt earlier output
       silently; it may only validate and explicitly reconcile it as identical or quarantine it.
                                                                                  
                                                                                  
       10.2 Formal schema layer                                                   
       Use dataclasses, Pydantic, JSON Schema, or equivalent versioned definitions for:
                                                                                  
       • campaign and explicit roster;                                            
       • resolved run configuration;                                              
                                                                                  
       • metric row;                                                              
       • history table;                                                           
       • site-observable table;                                                   
       • correlation-observable table;                                            
                                                                                  
       • checkpoint metadata and parameter-tree summary;                          
       • artifact manifest;                                                       
       • completion record;                                                       
                                                                                  
       • registry terminal-state record.                                          
       Unknown fields should be either forbidden or explicitly namespaced. Required row counts and index ranges must
       be derived from N, sampler settings, and iteration count.

       10.3 Actual checkpoint validation                                          
                                                                                  
       The validator must call the production restore routine and check:          
       • the file is loadable;                                                    
                                                                                  
       • PyTree names, shapes, dtypes, and parameter count match the model contract;
       • all real and imaginary values are finite;                                
                                                                                  
       • model, basis, boundary, N, and protocol identities match;                
       • a small deterministic amplitude or observable probe reproduces stored values within tolerance.
                                                                                  
       10.4 Heartbeat and fencing                                                 
                                                                                  
       Eachclaimreceivesacryptographicallyrandomattempt_id. Theworkerheartbeatsatafractionofthelease. Every
       state transition includes WHERE attempt_id = ? AND status = ?. A stale worker’s late bundle is preserved
       under an attempt directory and quarantined; it never becomes canonical without an explicit byte-identical
       reconciliation decision.                                                   
                                                                                  
       10.5 Fallback orchestration if closure fails                               
                                                                                  
       The scheduler is not the research contribution. If Stage 4F.1c fails structurally, use a simpler design:
                                                                                  
       1. partition the frozen roster into immutable per-host shard files;        
       2. run one local registry per host, never over a network filesystem;       
       3. write content-addressed per-run bundles;                                
                                                                                  
       4. collect bundles into a staging area;                                    
       5. run one offline strict merger that rejects duplicates, omissions, and identity conflicts;
       6. regenerate a final root manifest and campaign table.                    
                                                                                  
       This sacrifices dynamic load balancing but dramatically reduces state-machine risk.

       12.1 Runtime and storage expectations                                      
                                                                                  
       Earlier Stage 4F evidence placed most non-RBM runs around one minute and RBM runs around one and a half
       minutes on the student CPU environment. These values are planning estimates, not Stage 4F.1b measurements.
       After a 32-run calibration, the 960-run campaign is likely in the range of tens of aggregate CPU-hours, with a
       multi-machine wall time of several hours if safely sharded. The greater risk is not raw compute; it is wasting
       compute through ambiguous completion and replay failure.                   
                                                                                  
       12.2 Machine allocation                                                    
                                                                                  
       • Tier 0–1: one CPU machine for schemas, adversarial validation, registry tests, and four-run smoke.
       • Tier 2: one stable workstation for the 16-run microcampaign and all-model calibration.
       • Tier 3: two to four machines with separate local registries or a single-host coordinator. Do not mount one
         SQLite WAL database across hosts.                                        
                                                                                  
       • GPU use: optional for real VMC throughput, but not required for scheduler validation. GPU workers must
         still write local transactional bundles and preserve exact environment/device metadata.
       • Colab: use only as an isolated shard worker with staged input/output, never as the owner of the canonical
         registry.                                                                
                                                                                  
       12.3 Checkpoint and resume design                                          
                                                                                  
       History must be flushed incrementally. Checkpoints and sidecars should be written to attempt-local temporary
       paths, fsynced, validated, and only then promoted. The scheduler should support resuming model optimisation
       from a verified intermediate checkpoint, but canonical completion must always represent a terminal, post-analysis
       bundle.
